CAD to URDF Pipeline: Assembling SO-101 in Onshape & Simulation Export

A hands-on engineering walkthrough transforming raw STEP CAD files into a validated, simulation-ready ROS URDF: assembling the SO-101 manipulator in Onshape and verifying joint kinematics in WebGL URDF Viewer.

Hardware & CAD Repo↗

1. Project Overview

Bridging mechanical CAD and robotics simulation requires translating static 3D geometry into a kinematically constrained robot description format (URDF). Without accurate joint axes, origin frames, and limit definitions, downstream ROS 2 control nodes, MoveIt motion planners, and MuJoCo/Isaac Sim digital twins cannot function.

This project was built as a focused, practical engineering showcase demonstrating how to take open-source mechanical CAD parts from The Robot Studio (SO-101), assemble the complete kinematic chain using mates in Onshape, export a clean ROS-compatible URDF package, and validate joint articulation using the RobotsFan URDF Viewer.

Toolchain & Pipeline Specifications

  • Source CAD Files: SO-101 STEP Files (The Robot Studio)
  • CAD Software: Onshape Cloud CAD (Parametric Assembly & Mates)
  • Exporter Tool: Onshape-to-URDF Exporter Plugin
  • Target Robot Format: ROS / ROS 2 Unified Robot Description Format (URDF)
  • Kinematic Tree: 6 Revolute Joints + 1 Prismatic/Revolute Gripper
  • Verification Platform: RobotsFan WebGL URDF Viewer

3. Step-by-Step Technical Implementation

Step 1: STEP Import & Component Organization in Onshape

Individual parts from the SO-ARM100 / SO-101 repository were imported into Onshape Part Studios. Hardware fasteners, smart bus servos, and 3D printed brackets were grouped into discrete logical links (Base, Shoulder Pan, Shoulder Pitch, Elbow Pitch, Wrist Pitch, Wrist Roll, and Moving Jaw Gripper).

Figure 1: Initial STEP import of SO-101 components into Onshape before mate assembly.

Step 2: Defining Kinematic Mates & Joint Coordinate Frames

In Onshape, a robot kinematic chain is built using Revolute Mates and Fastened Mates:

  • Z-Axis Alignment: ROS standards mandate that a revolute joint’s rotation occurs about its local ZZZ-axis. Mates were placed at the exact rotational centerlines of the servo horn bearings with the mate connector’s ZZZ-axis pointing along the actuation axis.
  • Fastened Sub-Assemblies: Servos, motor brackets, and bearing retaining plates were rigidly fastened to their respective parent link bodies to merge them into single rigid bodies for the exporter.
  • Joint Limits: Physical travel limits (matching the Feetech STS servo rotation ranges) were directly assigned in Onshape mate limits to prevent mechanical collision during simulation.

Figure 2: Fully assembled SO-101 manipulator with defined revolute mates and coordinate origin connectors.

Step 3: URDF Package Export

Using the Onshape URDF exporter extension, the assembly tree was processed into a standard ROS package structure:

  • urdf/so_arm101.urdf: Contains XML tags specifying parent/child link hierarchies, origin translations, rotational vectors, and limit tags.
  • meshes/: Generated triangulated surface meshes (.stl) for both high-fidelity visual rendering and simplified collision boundaries.
  • launch/: Standard display launch script for visualization.

Figure 3: Configuring link names, mesh export parameters, and downloading the completed URDF package.

Step 4: WebGL Viewer Verification

The generated package was uploaded to RobotsFan URDF Viewer to perform interactive validation:

  • Checked for detached child meshes (a common CAD-to-URDF error caused by unfastened sub-parts).
  • Checked joint origin offsets and confirmed zero-angle default pose.
  • Dynamically swept each joint through its full range of motion.

Figure 4: Visual verification in RobotsFan URDF Viewer showing active joint sliders and aligned collision envelopes.
